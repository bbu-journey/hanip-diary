# 한 입의 기억

직접 다녀온 맛집과 여행지를 기록하고 여행 코스로 공유하는 한국어 GitHub Pages 사이트입니다. 별도 서버나 유료 서비스 없이 동작합니다.

## 사용하는 순서

1. 사이트 하단 **내 기록 관리**를 열고 **장소 기록하기**를 누릅니다.
2. 사진, 지역, 별점, 메뉴, 메모를 작성합니다. 관광지는 장소 종류를 **여행지**로 고릅니다.
3. 같은 **여행 이름**을 입력한 장소는 **여행 며칠째 → 그날의 방문 순서**로 묶입니다.
4. **공개할 기록에 포함하기**를 선택해도 즉시 게시되지 않습니다. 우선 이 기기에 저장합니다.
5. **공개 화면 미리보기**로 공개할 내용을 확인합니다.
6. **공개하기**에서 GitHub에 게시하면 누구나 사이트를 열어볼 수 있습니다. 방문자는 **코스 공유**로 특정 여행의 링크를 보낼 수 있습니다.

예시 구경하기에 나오는 장소·후기는 가상의 예시입니다. 실제 기록에 저장되거나 게시되지 않습니다. 처음에는 실제 방문 기록이 비어 있습니다.

## GitHub Pages 최초 배포

### 웹에서 파일 업로드로 시작

1. [GitHub 새 저장소](https://github.com/new)에서 `hanip-diary`라는 **Public** 저장소를 만들고 README 생성을 켭니다.
2. 이 폴더의 `index.html`, `styles.css`, `app.js`, `core.js`, `storage.js`, `favicon.svg`, `public.json`, `assets` 폴더를 저장소 루트에 업로드합니다. `assets` 폴더도 함께 올려야 이미지가 보입니다. 개인 백업 파일은 올리지 마세요.
3. 저장소 **Settings → Pages → Build and deployment → Source**에서 **Deploy from a branch**, **main**, **/(root)**를 선택하고 Save를 누릅니다.
4. 배포가 완료되면 `https://계정이름.github.io/hanip-diary/`로 접속합니다.

### Git 또는 GitHub Desktop으로 전체 폴더를 올리는 경우

이 폴더에는 `.github/workflows/pages.yml`이 포함되어 있습니다. 전체 폴더를 `main` 브랜치에 올리고 **Settings → Pages → Source → GitHub Actions**를 선택하세요. 워크플로가 테스트 후 사이트 파일만 배포합니다. 최초 실행이 설정 전에 실패했다면 Actions에서 다시 실행합니다. 이 방식과 위의 브랜치 배포 중 하나만 사용하세요.

[GitHub Pages 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

## 일상적인 게시: 두 가지 방법

### 사이트에서 바로 게시

1. GitHub **Settings → Developer settings → Personal access tokens → Fine-grained tokens**에서 본인의 사이트 저장소 하나만 선택한 연결 키를 만듭니다.
2. Repository permissions에서 **Contents: Read and write**만 부여하고 만료일을 설정합니다.
3. 사이트의 **공개하기**에 `계정/저장소`와 키를 입력해 **게시할 저장소 확인**을 누릅니다.
4. 게시 대상과 공개 수를 확인하고 **확인한 공개 기록으로 페이지 업데이트**를 누릅니다.

키는 현재 페이지 메모리에만 유지되며 소스, 백업, 브라우저 저장소에 보관하지 않습니다. 새로고침하면 다시 입력해야 합니다. 키를 채팅이나 소스 파일에 붙여넣지 마세요. 연결 키가 만료되면 새 키를 만듭니다.

게시할 때 저장소 기본 브랜치의 `public.json` 전체를 교체합니다. 새 기기에서 게시하기 전에는 기존 기기의 **백업 전체를 복원**해야 기존 공개 기록이 사라지지 않습니다. 다른 곳에서 파일이 변경되면 GitHub의 SHA 충돌 검사가 덮어쓰기를 막습니다. 정적 GitHub Pages 환경이므로 GitHub 로그인만으로 자동 인증하는 기능은 포함하지 않았습니다.

### 연결 키 없이 게시

**공개하기 → 연결 키 없이 파일로 올리기 → 공개용 public.json 내려받기**를 누르고, GitHub 저장소의 `public.json`을 이 파일로 교체합니다. 이것도 선택한 공개 기록 전체의 스냅샷입니다. **개인 백업 파일과 공개용 파일은 다릅니다.**

게시 성공 안내는 GitHub 파일 저장 성공을 의미합니다. 실제 사이트 반영은 GitHub Pages 배포 완료 후이며 몇 분 걸릴 수 있습니다. 소스 커밋 권한이나 브랜치 보호 규칙이 게시를 막으면 GitHub 설정을 확인하세요. 자동 게시 파일 크기는 8MB까지입니다.

## 개인 기록과 공개 기록

- 개인 기록·사진: 사용하는 기기의 브라우저 IndexedDB에 보관됩니다. 다른 기기로 자동 동기화되지 않습니다.
- 공개 사이트: 저장소의 `public.json`만 읽습니다. 공개 선택한 기록의 사진·방문일·메모·별점·여행 이름이 포함됩니다.
- 공개 선택을 해제하거나 기록을 삭제한 뒤에는 **공개하기를 다시 실행**해야 기존 공개 페이지에 반영됩니다.
- 한 번 공개한 자료는 GitHub 커밋 이력이나 타인의 복사본에 남을 수 있습니다. 최신 페이지에서 비공개로 전환해도 과거 이력이 자동 삭제되지는 않습니다.
- 사이트의 **내 기록 관리**는 각 방문자 자신의 기기 저장 공간을 여는 화면입니다. 다른 방문자는 아내분의 기기 기록을 보거나 수정할 수 없습니다. 공개 페이지 변경에는 해당 저장소 쓰기 권한이 필요합니다.
- 로컬 미리보기와 실제 GitHub 주소의 브라우저 저장 공간은 서로 다릅니다. 미리보기에서 작성한 기록은 백업 후 배포 사이트에서 복원하세요.
- 새 기기 사용, 브라우저 데이터 삭제 전에는 **백업과 복원 → 모든 기록 백업하기**를 사용하세요. 사진까지 JSON 파일에 포함됩니다. 복원 시 기존 기록은 유지되고, 같은 ID는 수정 시각이 더 최근인 기록을 남깁니다.
- 사진은 최대 1,000px JPEG로 변환하고 원본 메타데이터를 복사하지 않습니다. HEIC를 읽지 못하는 브라우저에서는 JPG로 변환해 업로드하세요.
- 삭제 후 표시되는 **되돌리기**는 현재 화면의 마지막 삭제를 복구합니다. 새로고침 후에는 백업으로 복원해야 합니다.

## 주소

- `./` : 사람들이 보는 공개 사이트
- `?edit=1` : 기기 내 기록 작성
- `?preview=1` : 내 기기에 있는 공개 선택 기록 미리보기 (공유용 주소 아님)
- `?trip=여행이름` : 게시된 특정 코스 보기. 사이트의 코스 공유 버튼을 사용하세요.

## 내 컴퓨터에서 실행

Node.js 22 이상에서 이 폴더를 열고 `npm start`를 실행하면 `http://127.0.0.1:4173/?edit=1`에서 작성할 수 있습니다. 의존성 설치나 빌드 단계는 없습니다. ES 모듈과 데이터 로딩을 사용하므로 `index.html`을 더블클릭하는 대신 웹 서버로 여세요.

`npm test`는 비공개 데이터 제외, 위험한 URL 차단, 백업 검증·병합, 코스 순서, 배포 파일 검사를 실행합니다.

글꼴은 Google Fonts를 사용하며 연결이 안 되면 시스템 글꼴로 표시합니다. 지도 링크는 네이버 지도 검색 또는 입력한 지도 URL을 엽니다. 외부 지도 API 키나 위치 권한은 요구하지 않습니다.

## 구성

순수 HTML/CSS/JavaScript. `core.js`는 데이터 검증과 공개용 직렬화, `storage.js`는 기기 저장, `app.js`는 화면과 GitHub 게시를 담당합니다. 프로필 제목과 소개는 사이트 설정에서 변경합니다. 빌드, 광고, 추적 스크립트가 없습니다.

장식 이미지 `assets/food-editorial.png`는 내장 ImageGen으로 생성한 일반 음식 이미지입니다. 실제 방문이나 식당을 나타내지 않습니다. 생성 프롬프트: “Photorealistic editorial overhead food still life: tomato burrata and basil, fork, folded burgundy napkin on light stone, natural sunlight, no people, text, or logos; supports a centered wide crop.”
